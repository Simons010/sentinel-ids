## 2025-02-14 - Removed hardcoded superuser credentials
**Vulnerability:** The application had hardcoded default superuser credentials (`d3fau1t` / `d3fau1t_Password!2026`) embedded within `create_default_admin.py`, `docker-compose.yml`, and `.env.example`. This could lead to a severe security risk if deployed without explicitly overriding these environment variables, as anyone could gain admin access to the application using these known default credentials.
**Learning:** Default credentials are a common attack vector. Hardcoding fallback values in configuration files or setup scripts is a dangerous anti-pattern because users may fail to set environment variables properly in production, inadvertently leaving the application secured with universally known passwords.
**Prevention:** Rely strictly on explicit environment variables for sensitive data like passwords. If required variables are missing, the application should fail securely or skip the creation process entirely, rather than resorting to hardcoded fallbacks. Always use placeholders (e.g., `your-secure-password-here`) in template or example files instead of functioning defaults.
