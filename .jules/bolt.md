## 2024-06-25 - Django ORM N+1 in Frequency Distributions
**Learning:** Iterative `.filter().count()` calls in Django views (e.g., when calculating frequency distributions for charts like `severity_counts` or `severity_breakdown`) cause N+1 query problems. Replacing these with a single `.values('field').annotate(count=Count('id')).order_by()` query significantly reduces database load. However, to ensure consistent API responses and grouping logic, it's crucial to pre-initialize the result dictionary with all expected keys set to zero, and use an empty `.order_by()` to clear any default model ordering that might otherwise interfere with the `.values().annotate()` grouping.
**Action:** Always replace iterative `.filter().count()` patterns with a single `.values().annotate()` query, initialize expected keys to 0, and clear default ordering with an empty `.order_by()`.
