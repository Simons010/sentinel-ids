## 2024-07-24 - Fix N+1 Query in Hourly Threat Data Aggregation
**Learning:** In Django, executing a loop with `.filter().count()` over time periods (like hourly stats in `DashboardStatsView` and `AnalyticsView`) results in N+1 database queries (72 queries for 24 hours), causing a severe performance bottleneck as data scales. Using `TruncHour` can cause timezone conversion issues with MySQL if timezone tables are not installed correctly in the environment.
**Action:** Use a single `.aggregate()` with dynamic `Count(..., filter=Q(...))` kwargs to batch the 24-hour aggregations into a single native database query. This drastically reduces query time (from ~180ms down to ~90ms for 5000 logs) and avoids the MySQL timezone table dependency issue while maintaining database-native speed.
